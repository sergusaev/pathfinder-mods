# Как Unity Mod Manager попадает в игру

[English version](umm.md)

Здесь объясняется, как устроена установка, а пошаговые команды — в справках [для Steam Deck](steam-deck.ru.md) и [для Windows](windows.ru.md). Прочитать стоит до установки или когда что-то сломалось: почти все поломки, которые мы встречали, описаны ниже.

## Из чего состоит установка

**Unity Mod Manager (UMM)** — программа, которая запускается внутри игры, находит папки модов и загружает их. Сама игра про моды ничего не знает, поэтому UMM нужно «подсунуть» игре при старте. Для этого есть два способа: **Doorstop** и **Assembly**. Мы используем только Doorstop.

После установки в папке игры есть:

| Файл или папка | Что это |
|---|---|
| `winhttp.dll` | загрузчик Doorstop: игра думает, что это системная библиотека Windows, и загружает её сама |
| `doorstop_config.ini` | настройка загрузчика: включён ли он и какой файл запускать |
| `<Игра>_Data/Managed/UnityModManager/` | сам UMM: `UnityModManager.dll`, `0Harmony.dll`, `dnlib.dll` и другие |
| `<Игра>_Data/Managed/UnityModManager/Config.xml` | описание игры для UMM: где папка модов и в какие места игры встраиваться |
| `<Игра>_Data/Managed/UnityModManager/Params.xml` | настройки UMM: показывать ли окно при старте, какие моды включены |
| `Mods/` | папка модов, в ней по папке на каждый мод |

`<Игра>_Data` — это `Kingmaker_Data` у Kingmaker и `Wrath_Data` у Wrath of the Righteous (WotR).

## Doorstop

Когда программа для Windows стартует, она загружает системные библиотеки. Одна из них — `winhttp.dll`. Windows сначала ищет её в папке самой программы и только потом в системной папке. Doorstop этим пользуется: в папку игры кладётся свой `winhttp.dll`. Игра загружает его вместо системного, он читает `doorstop_config.ini` и запускает файл из строки `target_assembly`, то есть `UnityModManager.dll`.

```ini
[General]
enabled = true
target_assembly = Kingmaker_Data\Managed\UnityModManager\UnityModManager.dll
```

- `enabled = true` — загрузчик включён. С `false` игра запускается без модов, а файлы остаются на месте.
- `target_assembly` — путь к UMM от папки игры. Для WotR вместо `Kingmaker_Data` пишется `Wrath_Data`. Обратная косая черта `\` нужна потому, что путь читает программа для Windows, даже на Steam Deck.

**Плюсы Doorstop:** файлы самой игры не меняются, добавляются только два новых. Обновление игры и «Проверка целостности файлов» в Steam их не трогают, UMM не пропадает.

## Assembly — почему мы его не используем

Способ Assembly дописывает вызов UMM прямо внутрь файла игры `<Игра>_Data/Managed/UnityEngine.UIModule.dll` (строка `EntryPoint` в `Config.xml`), а оригинал сохраняет рядом с именем `UnityEngine.UIModule.dll.original_`.

Проблема в том, что это изменённый файл игры. Как только Steam обновляет игру или проверяет целостность файлов, он молча возвращает исходный `UIModule.dll`. UMM после этого просто не запускается: ни ошибки, ни окна, моды лежат в папке, но не работают. Так и случилось на Steam Deck, поэтому все наши справки ставят UMM только через Doorstop.

Если UMM уже ставился способом Assembly, его признак — файл `UnityEngine.UIModule.dll.original_` в папке `Managed`. Чтобы перейти на Doorstop: удалить UMM способом Assembly (в установщике — кнопка удаления, или вернуть `.original_` на место), либо проверить файлы игры в Steam, затем поставить по справке.

## Параметры запуска

**На Windows параметры запуска не нужны**: Windows сама берёт `winhttp.dll` из папки игры.

**На Steam Deck (и в любом Linux через Proton)** обе игры запускаются в Proton, а это Wine — слой, который выполняет программы для Windows. У Wine есть свои встроенные копии системных библиотек, и для `winhttp.dll` он по умолчанию берёт свою, а файл из папки игры не замечает. Поэтому в Steam для каждой игры задаются параметры запуска:

```
WINEDLLOVERRIDES="winhttp=n,b" %command%
```

Разбор по частям:

| Часть | Значение |
|---|---|
| `%command%` | сюда Steam подставляет обычную команду запуска игры (Proton + `Kingmaker.exe` или `Wrath.exe`). Без `%command%` Steam посчитает всю строку аргументами игры, и ничего не сработает |
| то, что **перед** `%command%` | переменные окружения: настройки, которые получит игра и Proton при запуске |
| `WINEDLLOVERRIDES=` | переменная Wine: «для этих библиотек бери не ту копию, что обычно» |
| `winhttp` | имя библиотеки без `.dll` |
| `n,b` | порядок поиска: сначала `n` (native — файл из папки игры, то есть Doorstop), если его нет — `b` (builtin — встроенная копия Wine) |
| кавычки `"…"` | держат значение `winhttp=n,b` одним куском; их нужно вводить прямыми кавычками `"`, а не «ёлочками» и не “типографскими” |

Отсюда два полезных следствия:

- **Выключить моды на время** можно, просто очистив параметры запуска: Wine возьмёт свою `winhttp.dll`, Doorstop не загрузится, файлы при этом остаются.
- **Без параметров** UMM на деке не запускается, даже если все файлы на месте. Это первое, что нужно проверять.

Нативная Linux-сборка Kingmaker запускалась по-другому, параметрами `./run.sh %command%` (подробнее — [ниже](#почему-не-нативная-linux-сборка-kingmaker)). С Windows-сборкой эти параметры не работают: Steam не найдёт `run.sh`, и игра не запустится.

## Config.xml и строка UIStartingPoint

`Config.xml` говорит UMM, в какие места игры встраиваться:

| Строка | Значение |
|---|---|
| `StartingPoint` | когда загружать моды: при старте игры (`Kingmaker.GameStarter.Awake`) |
| `UIStartingPoint` | когда создавать окно UMM: после запуска главного меню (`Kingmaker.MainMenu.Start`). Если строки нет, окно создаётся сразу в `StartingPoint` |
| `EntryPoint` | куда встраиваться способу Assembly; для Doorstop не используется, но не мешает |
| `ModsDirectory` | имя папки модов, у нас `Mods` |

**Kingmaker: строку `UIStartingPoint` нужно удалить.** Именно она сломала UMM на Steam Deck. У Kingmaker два разных интерфейса: для мыши и клавиатуры и консольный, для геймпада, со своим главным меню. `Kingmaker.MainMenu.Start` — это главное меню интерфейса для мыши. В режиме геймпада оно не запускается никогда, и UMM не создаёт своё окно. Внешне это выглядит так:

- пункт «Unity Mod Manager» в меню игры есть, но ничего не открывает (в логе ошибка `NullReferenceException`);
- моды загружены, их кнопки и карточки видны, но многие не действуют: UMM вызывает их обработку каждого кадра (`OnUpdate`) из своего окна, а окна нет;
- в режиме мыши и клавиатуры всё работает, поэтому поломку легко принять за проблему управления.

Установщик UMM и пакет UMM записывают `Config.xml` со строкой `UIStartingPoint` для обеих игр. Поэтому после **каждой** установки или переустановки UMM в Kingmaker строку нужно проверить и удалить; команды — в справках для [Steam Deck](steam-deck.ru.md#4-unity-mod-manager-для-kingmaker) и [Windows](windows.ru.md#3-убрать-uistartingpoint-у-kingmaker).

**WotR: строку оставить.** В WotR одно главное меню на оба режима, и окно UMM с этой строкой работает и с геймпадом, и с мышью (проверено с геймпадом на Steam Deck и с мышью на Windows).

## Почему не нативная Linux-сборка Kingmaker

В Steam у Kingmaker есть сборка для Linux, и на Steam Deck Steam ставит её по умолчанию. Мы от неё отказались:

- **Неисправимая ошибка игры:** в режиме геймпада окно управления королевством открывается, а закрыть его нельзя — игра застревает. Ни моды, ни настройки этого не исправляют.
- Нужен отдельный загрузчик для Linux (`libdoorstop.so` + скрипт `run.sh` с параметрами запуска `./run.sh %command%`), который надо править под игру вручную.
- Регистр имён важен: `Mods` и `mods` — разные папки, `Info.json` и `info.json` — разные файлы.
- Логи и сохранения лежат в другом месте (`~/.config/unity3d/Owlcat Games/Pathfinder Kingmaker/`), а не в префиксе Proton, как у WotR.
- Сохранения нативной сборки и Windows-сборки в разных папках, при переходе их нужно переносить руками.

Windows-сборка под Proton устроена так же, как WotR и как на ПК с Windows: тот же Doorstop, те же параметры запуска, логи и сохранения в префиксе Proton. Как включить Proton для Kingmaker — в [справке для Steam Deck](steam-deck.ru.md#1-перед-началом).

## Моды независимы друг от друга

- Моды этого репозитория можно ставить **в любом порядке и в любом наборе**. Ни одному не нужен другой: в `Info.json` у всех пустой список `Requirements`, а общий код (окна модов, блокировка галочек) собран внутрь каждого мода. Если какого-то мода нет, остальные работают как обычно.
- Удобнее всего начать с [Unity Mod Manager in Game Menus](../umm-menu-button/README.ru.md): он добавляет пункт «Unity Mod Manager» в меню игры, и окно UMM открывается без клавиатуры.
- Галочки включения модов в окне UMM работают только в главном меню игры. В загруженной игре они заблокированы, чтобы мод не выключился посреди партии.
- Некоторые наши моды **заменяют** чужие или старые, и тогда старую папку нужно убрать, иначе одно и то же будет сделано дважды. Список — в [справке по установке модов](mods.ru.md#что-заменяет-что).

## Кэш UMM

При загрузке UMM кладёт рядом с DLL мода копию с расширением `.cache` и в следующий раз может загрузить её. После ручного обновления мода удаляйте `*.cache` в его папке, иначе может загрузиться старая версия. Команды — в [справке по установке модов](mods.ru.md#обновление).
